# v1.6 product delta — real tidal current data, provider-ready, key-gated

Baseline: v1.5 (`31ab919`). Research Gate result: the KHOA 수치조류도 지점별 최강창낙조 contract is
now **fully verified** directly against KHOA's own portal (`research/marine-current-source-review.md`)
— not `TBD_PROVIDER_CONFIRMATION` like every prior pass. This delta builds the provider/Worker/domain
boundary against that verified contract, gated behind a credential the user has not yet supplied.

## Answer to the core question (§0 of the prompt)

The KHOA 수치조류도 API provides: **location** (lon/lat, nearest-point within 1km) — yes; **time**
(10-minute predicted timestamps) — yes; **speed** (cm/s) — yes; **direction** (deg) — yes, but its
convention (toward/from, true/magnetic north) is not stated anywhere in the official contract; **sea
temperature** — no, this API does not provide it (KHOA fishing-index's `minWtem`/`maxWtem` remains
the only temperature source in this project, and is not conflated with this API's output). All five
are used or explicitly marked UNKNOWN based only on what the verified contract actually states.

## New requirements

- `REQ-FUNC-MARINE-001`: `KhoaTidalCurrentProvider` connects to the verified KHOA contract via the
  Worker's new `/api/marine-current` route. Speed and timestamp are used as-is; direction is carried
  with an explicit `directionConvention: 'UNKNOWN'` — never presented as if the convention were known.
- `REQ-FUNC-MARINE-002` (spatial provenance): every `MarineCurrentObservation` carries the requested
  `latitude`/`longitude` and is explicitly a nearest-point match, per KHOA's own "가장 가까운 지점
  (최대 1km)" — never presented as an exact-location reading. Distance from the requested point is
  not computable from this API's response (it only echoes the request lon/lat, not the matched
  station's own coordinate), so a "선택 위치에서 약 N km" label is not shown — the UI instead states
  "선택 위치에서 가장 가까운 지점(최대 1km) 기준" per the contract's own stated bound.
- `REQ-FUNC-MARINE-003` (temporal provenance): `observationType: 'FORECAST'` always (KHOA's own
  "예측" wording) — never labeled as an observation.
- `REQ-FUNC-MARINE-004` (speed/direction separation): `speed`/`speedUnit` (cm/s) and
  `direction`/`directionUnit`/`directionConvention` are independent fields; a response with a parse
  failure on one never blanks the other.
- `REQ-FUNC-MARINE-005`: N/A this release — no separate observed-SST source was found to be
  distinct from the KHOA fishing-index temperature; not implemented.
- `REQ-FUNC-MARINE-006` (partial preservation): reuses the v1.5 retry/classify helpers
  (`classifyFailure`) from `live-provider.ts` — no duplicate retry logic.
- `REQ-FUNC-GUIDANCE-007`: `CURRENT_SPEED`/`CURRENT_DIRECTION` guidance factors remain `UNKNOWN` for
  all 6 supported species — no SpeciesProfile has a cited numeric current threshold (re-confirmed by
  a targeted 참돔 search this pass). Connecting the data source does not add a guidance factor by
  itself; only cited evidence does.
- `REQ-NFR-MARINE-001`: `KHOA_MARINE_SERVICE_KEY` is a Worker secret, never in the browser bundle —
  same pattern as `KHOA_FISHING_SERVICE_KEY`. It is a **separate credential** on a separate khoa.go.kr
  key-issuance system; `KHOA_FISHING_SERVICE_KEY` cannot be reused here (verified, not assumed).
- `REQ-NFR-MARINE-002` (GPS minimization): the Worker rounds `lon`/`lat` to 3 decimal places
  (~110m precision) before both the upstream call and the cache key — well inside the API's own
  1km nearest-point tolerance, so no precision is lost that the API would have honored anyway, while
  the exact GPS-derived coordinate is never the literal cache key or upstream parameter.
- `REQ-NFR-MARINE-003`: cache TTL is 10 minutes, matching the API's own stated 10-minute data
  resolution — not a copy-pasted 5-minute value from the fishing-index route.

## Scope explicitly not built this release

- No live UI wiring into `LiveApp.tsx`/`OfficialIndexPanel.tsx`. Rationale: without
  `KHOA_MARINE_SERVICE_KEY` set, a wired UI would only ever render "연결되지 않음" in production —
  indistinguishable from not having built it, while adding UI surface, tests, and visual-review scope
  that cannot be verified against real data in this session. The provider/Worker/contract layer is
  complete and tested end-to-end against sanitized real-shaped fixtures; wiring it into the detail
  panel is a small, low-risk follow-up once the user supplies the key (see §65 setup below), and is
  the recommended very next step, not a deferred research question.
- No map vector visualization (explicitly optional per §43 of the prompt).
- No temperature-front / water-mass inference (explicitly out of scope per §36).
- Direction convention stays UNKNOWN; no assumption is coded anywhere.

## Setup required (not fabricated)

1. Register at khoa.go.kr, agree to Open API terms, submit a key request for
   "수치조류도 지점별 최강창낙조" (사용목적/서비스/사용기관/사용URL).
2. `npx wrangler secret put KHOA_MARINE_SERVICE_KEY` in `worker/`.
3. No frontend env var needed — the existing `VITE_FISHING_API_BASE_URL` Worker origin already serves
   the new route once the secret exists.
