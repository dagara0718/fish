## User request and decision (2026-09-27)

After an arbitrary map click the app lists the nearest official points and the user picks one, so
the data shown is for a different location — the user found that low-trust and asked for "species
likely to appear, compared across nearby points". Decision (user-confirmed): **no probability**.
The official index is a per-point "낚시 여건" grade, not a species-occurrence or catch probability,
and the clicked location has no official value; averaging or interpolating neighbours into a
probability would fabricate evidence (constitution III/IV; existing species-guidance e2e F forbids
probability/recommendation wording). Instead: an on-request, clearly-labelled comparison of the
nearest official points' own grades.

## Found during verification — Worker cache hits lacked CORS (pre-existing since `443c25a5`)

`proxyUpstream` returned cache hits as a bare `Response` without the `Access-Control-Allow-Origin`
header, so browsers blocked every repeat request within the cache TTL (catalog pages, detail lookups).
This is also the likely cause of the "CORS on page 3+" failures seen from localhost during v1.6.3.
Fixed by routing cache hits through `reply()`; regression test "returns cached bodies with the same
CORS headers" fails without the fix and passes with it. Worker redeployed (version `7614174b`).
