# v1.6.3 product delta — tidal-current forecast in the live brief

Baseline: `e401f07` (v1.6.2 marine alternate proxy, Vercel ESM fix). v1.6.2 deferred Production UI
wiring (`v1.6.2-result.md` "Configuration boundary for the next version"); this delta is that step.
No existing Requirement ID changes meaning. The official fishing index, its Cloudflare Worker, NAVER
map viewport handling, TrustStatus (5 values), and species guidance are unchanged.

## Scope

After an **explicit** official-point selection, `LiveApp` fetches the official fishing index and the
KHOA tidal-current forecast **concurrently and independently**, and the brief shows a compact
tidal-current forecast summary with state, time, trust and provenance. Display-only:
`CURRENT_SPEED`/`CURRENT_DIRECTION` stay `UNKNOWN` for every species (REQ-FUNC-GUIDANCE-007).

## Findings that shaped the delta (2026-09-24)

1. **Time basis is not documented.** KHOA's own API page (`openApiDetail.do?id=18`, rendered in a
   real browser) and the data.go.kr listing (`15039013`) give `SDate/SHour/SMinute` and `obs_date`
   formats but never state KST or UTC. A 200 response cannot settle it (a forecast service answers any
   window; both a UTC-now and a KST-now window returned rows). **Status: TBD, not guessed.**
2. The v1.6.3 draft built the request window with `getUTC*` and called UTC "more conservative" — an
   unsourced assumption, and one that would show a window 9 h in the past if KHOA is KST. Replaced.
3. **`type` is mostly empty.** In a 10 h live window (public 가거도 point, 34.073/125.088) 58 of 61 rows
   had `type: ""`; three event rows were labeled 최강낙조류 (70 cm/s), 전류 (2 cm/s), 최강창조류 (67 cm/s).
4. **`전류` means 전류(轉流), the current's turn**, not an "instantaneous current" as v1.6 read it —
   the labeled 전류 row sits at ~2 cm/s midway between the two peaks. The enum is renamed
   `INSTANTANEOUS` → `SLACK`; the UI shows KHOA's label verbatim.
5. The proxy returns numeric `current_speed`/`current_dir` (KHOA's sample shows strings). Both accepted.
6. An inland coordinate returned proxy `502 MALFORMED_RESPONSE`. Direct upstream probing (below)
   showed KHOA answers HTTP 200 `{"result":{"error":"No search data"}}` for inland (37.566/126.978) and
   out-of-model open ocean (32.000/130.500), while past (2000) and future (2099) windows at a sea point
   return data — but the same text also comes back for an end-before-start window. Follow-up fix
   (REQ-FUNC-MARINE-UI-008): the proxy rejects end-before-start windows with 400, then maps the exact
   `No search data` shape to `422 NO_DATA_FOR_LOCATION`, which the client shows as unsupported area.
7. **KHOA did not enforce `ServiceKey`** on this endpoint during probing: requests with no key or an
   invalid key returned the same data. Not relied on — the proxy still sends the registered key, and
   the key stays server-only.

## New requirements

- `REQ-FUNC-MARINE-UI-001` (explicit trigger, own coordinate): the marine request is made only after
  "이 포인트 선택" (or its re-query/retry), with the selected official point's own public coordinate
  (rounded to 3dp). Search, marker/list preview, arbitrary map click and GPS never call it; raw GPS is
  never sent, stored, or put in a URL.
- `REQ-FUNC-MARINE-UI-002` (finite states): the panel renders a distinct, text-labeled state for
  not configured (`NOT_CONNECTED`: unset/invalid base URL or proxy 503), loading, success, partial,
  unsupported area, failure (`UNAVAILABLE`, marine-only retry), and stale. It never silently
  disappears after a selection, never shows raw errors/stack/secrets, and never falls back to demo data.
- `REQ-FUNC-MARINE-UI-003` (provenance): shows the reused `TrustBadge` (per row in evidence and at
  section level), source name, forecast window, retrieval time (this device's clock, labeled KST)
  separately from forecast time, the 1 km nearest-point spatial basis, "예측값 · 실측 아님",
  unconfirmed direction convention and unconfirmed time basis, behind a keyboard-operable `<details>`.
- `REQ-FUNC-MARINE-UI-004` (independence/cancellation): marine loading/error is independent of the
  official index; a marine failure never hides a successful index. Marine has its own
  `AbortController`: point change, re-search, arbitrary map click and unmount cancel it; a superseded
  response never overwrites a newer point; a cancelled request leaves no loading state; a marine-only
  retry does not refetch the index.
- `REQ-FUNC-MARINE-UI-005` (time basis TBD): `timeBasis: 'UNCONFIRMED'` on every row. The request
  window runs from (now as a UTC wall clock − 30 min) to (now as a KST wall clock + 30 min), so the real
  present is inside it under either reading. No row is marked "지금/현재/실시간"; the UI states why.
- `REQ-FUNC-MARINE-UI-006` (empty type): `type: ""` is kept as "미표기", never inferred; an unknown
  non-empty label is dropped as malformed and the result becomes `PARTIAL`.
- `REQ-FUNC-MARINE-UI-007` (staleness): once the retrieval is older than 10 min (the data's own
  resolution, REQ-NFR-MARINE-003) the section shows `STALE` in addition to the rows' `UNVERIFIED`,
  with a marine-only refresh — no automatic refetch.
- `REQ-FUNC-MARINE-UI-008` (unsupported area): the marine proxy returns `422 NO_DATA_FOR_LOCATION`
  only for KHOA's exact `{"result":{"error":"No search data"}}` on a validated (end ≥ start) window;
  any other error shape stays a 502 failure. The client maps 422 to `UNSUPPORTED_AREA` with no retry.
- `REQ-NFR-MARINE-004` (config boundary): `VITE_MARINE_API_BASE_URL` (GitHub Actions Variable
  `MARINE_API_BASE_URL`) is separate from `VITE_FISHING_API_BASE_URL`. `KHOA_MARINE_SERVICE_KEY`
  exists only on the Vercel server; no KHOA key or NAVER Client Secret enters the bundle.
