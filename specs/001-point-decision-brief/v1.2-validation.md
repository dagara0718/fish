## Defects found and fixed during validation

1. **`LiveOfficialFishingIndexProvider` could never fetch in a browser.**
   The default constructor argument stored a bare `fetch` as an instance property, so calls executed with the
   provider as receiver and threw `TypeError: Failed to execute 'fetch' on 'Window': Illegal invocation`.
   Node's `undici` tolerates the unbound call, so unit tests with an injected mock passed while every real
   browser search failed into `COLLECTION_FAILED`. Fixed with a bound wrapper in
   `src/official-index/live-provider.ts`; regression is covered by `e2e/live-map.spec.ts`.
2. **Trust badge rendered as a full-width block inside 현재 환경.**
   `.environment-item > span` (specificity 0,2,0) overrode `.trust-badge { display: inline-flex }`. Fixed with a
   scoped `.environment-item > .trust-badge` rule in `src/styles/global.css`.

## Boundary verification

- **Demo/Live separation.** Live is the default mode. A Live failure surfaces `COLLECTION_FAILED` or an explicit
  status message and never substitutes fixture data — asserted by `e2e/live-map.spec.ts` ("Live proxy failure never
  displays demo fallback") and by `tests/unit/live-provider.test.ts`. Synthetic points appear only after the user
  explicitly selects Demo 모드 and are never labelled as official fishing-index points.
- **Explicit selection.** Map marker clicks and list clicks only set a preview. The brief is produced solely by the
  `이 포인트 선택` action. No nearest-point auto-selection exists on any path.
- **GPS privacy.** Coordinates live in component state only. The E2E run asserts `localStorage.length === 0` and that
  raw coordinates never reach the URL. Provider requests carry only `gubun`, `reqDate`, `placeName`, `pageNo`,
  `numOfRows`; the absence of `latitude`/`longitude` in the request URL is asserted in the unit tests.
- **Secret boundary.** `KHOA_FISHING_SERVICE_KEY` exists only as a Cloudflare Worker secret. The Worker pins a fixed
  upstream, allowlists parameters, validates `gubun`/`reqDate`/`numOfRows`, restricts CORS origins, applies a 10s
  timeout and a rate limit, and refuses to emit any response containing the key (raw or percent-encoded).
  `VITE_NAVER_MAP_NCP_KEY_ID` is a browser-scoped Web SDK identifier and is deliberately treated differently from
  the public-data service key.
- **Trust semantics.** Official grade/score and `TrustStatus` remain separate labels. No freshness number or
  environment unit absent from the official Swagger is synthesized; unknown units render as `단위 미확인`.

## Blocked — requires real credentials and an external account

These cannot be completed without the user's own keys and are deliberately not marked done:

1. `VITE_NAVER_MAP_NCP_KEY_ID` — not set locally (`.env.local`) or as the `NAVER_MAP_NCP_KEY_ID` GitHub secret, so
   production renders the `NAVER 지도 설정이 필요합니다.` fallback instead of real tiles. The fallback is graceful:
   search, candidate list and brief remain fully usable.
2. `KHOA_FISHING_SERVICE_KEY` — not registered via `npx wrangler secret put`, and the Worker is not deployed, so
   `VITE_FISHING_API_BASE_URL` / the `FISHING_API_BASE_URL` Pages variable are unset. Live mode therefore shows the
   `실시간 공식 데이터 연결이 설정되지 않았습니다.` notice.

No account was created and no credential was fabricated. End-to-end verification against the real NAVER SDK and the
real 국립해양조사원 upstream remains outstanding and is explicitly excluded from the PASS results above.
