**Selected: Vercel Functions.** It is the only candidate with a CLI already present in this
environment, requires no payment method for the free Hobby tier, and its Node.js Serverless Functions
run on regional AWS-backed compute rather than a global CDN edge — a genuinely different network path
from Cloudflare Workers, which is the actual variable this PoC needs to isolate (not "Korea vs.
not-Korea" — see v1.6.1's own finding that a non-Korean-network direct `curl` succeeded fine).
AWS/GCP were not pursued further because neither CLI nor credentials exist in this environment and
both have a credible chance of requiring billing setup at account-creation time, which the prompt
explicitly says not to do without approval.

## Security / privacy

- **Secret**: `KHOA_MARINE_SERVICE_KEY` is read only from `process.env` inside the Vercel function; it
  is never in `marine-proxy`'s source, never in a committed file, never in a response body (redaction
  test passes), never logged. This report does not contain and did not request the key's value.
- **GPS**: `lat`/`lon` rounded to 3 decimal places before being placed in the upstream request URL;
  no server-side cache exists this PoC, so there is no cache-key exposure surface to check.
- **SSRF**: the upstream hostname/path (`https://khoa.go.kr/oceandata/api/tidalCurrentPoint/search.do`)
  is a source-code constant; no request parameter can influence host, path, or protocol — verified by
  the param allowlist rejecting any key outside the fixed `MARINE_PARAMS` set (test: "rejects
  invalid/duplicate/unknown params").
- **CORS**: same allowlisted-origin set as the Cloudflare Worker
  (`https://dagara0718.github.io`, `http://localhost:5173`, `http://127.0.0.1:5173`) — no wildcard.
- **Logging**: only `host`, `httpClass`, `upstreamStatus`, `elapsedMs`, `server`, `contentType`,
  `date` on a non-2xx upstream response — never the secret, never the upstream body, never exact GPS.

## Analyze

CRITICAL: 0. HIGH: 0.

- Secret leakage: none found — grepped the diff before staging; the real `KHOA_MARINE_SERVICE_KEY`
  value was never printed, copied, or referenced by value anywhere in this session's output or files.
- CORS: allowlisted origins only, no wildcard, verified by test.
- SSRF: upstream fixed by source constant, param allowlist rejects any host/path/protocol-shaped
  input, verified by test.
- Open proxy: the function accepts exactly two routes (`/api/marine-current`, `/api/health`); no
  generic passthrough exists.
- Parameter injection: allowlist + per-field validation (date/hour/minute/coordinate/ResultType),
  duplicate-key rejection, verified by test.
- Exact GPS: 3dp rounding before any outbound use; no server cache this PoC, so no cache-key exposure
  surface.
- Logs: field-limited diagnostic logging only, no secret/body/exact-GPS, matches the Worker's own
  v1.6.1 diagnostic pattern.
- Billing surprise: none — no paid plan, no payment method, no resource created; deployment itself is
  blocked pending the user's own login, which was reported rather than bypassed.
- Unbounded retry: none — the proxy makes exactly one upstream attempt per request; a bounded 10s
  timeout aborts a hung request; retry is left entirely to the frontend's existing `fetchWithRetry`.
- Response validation: the shared `validateMarineResponse` schema guard is exercised by both the
  Worker's and the proxy's test suites against the same shape.
