# Design Brief: 신뢰상태 기반 낚시 포인트 판단 브리프

**Date**: 2026-09-16
**Base Design System**: 프로젝트 루트 `DESIGN.md` (읽기 전용)
**Decision in scope**: OD-06 탐색 UI 구조
**Decision out of scope**: 외부 지도 SDK/API, 실제 공급자, 판단 브리프 최소 정보세트

## 제품과 사용자 과업

낯선 육상 바다낚시 포인트를 검토하는 사용자가 지원 포인트를 정확히 식별하고, 현재
이용 가능한 판단정보를 신뢰상태와 함께 한 단위로 살핀다. 제품은 출조·법적 가능 여부를
판정하지 않고, 불확실성과 근거를 오해 없이 전달해 사용자의 최종 판단을 돕는다.

## Design 목표

1. 포인트명·지역으로 탐색을 빠르게 시작하고 동일·유사 명칭을 명확히 구분한다.
2. `CONFIRMED`, `STALE`, `UNVERIFIED`, `COLLECTION_FAILED`, `CONFLICT`를 색상 외 텍스트와
   아이콘으로 구분해 정보상태 오해를 막는다.
3. 부분 실패에서도 성공한 판단정보를 유지하고 실패 범위를 국소적으로 보여준다.
4. source/time/status와 확인 경로는 항상 접근 가능하게 하되 1차 브리프를 과밀하게 만들지
   않는다.
5. 외부 지도 서비스 없이도 P1 흐름이 완결되도록 한다.

## Base Design System 적용

- 밝은 흰색 canvas, soft gray surface, ink/body/muted 텍스트 위계를 기본으로 한다.
- 파란색 primary는 주요 행동에만 드물게 사용한다. 상태 의미나 “낚시 가능” 의미로 쓰지 않는다.
- 입력은 12px radius, 행동은 pill, 카드 컨테이너는 24px radius를 기준으로 한다.
- hairline 중심으로 행과 카드 경계를 구분하고 그림자는 한 단계만 최소 사용한다.
- 큰 제목은 Inter 대체 서체 weight 400, 본문은 Inter 400/600, 숫자·시각은 tabular mono 대체
  서체를 사용한다.
- 4px spacing 체계와 1200px 최대 폭을 따르되, 제품 화면은 마케팅 페이지보다 높은 정보 밀도를
  허용한다.
- Coinbase 로고, 브랜드명, 암호화폐 문구·그래픽·마케팅 패턴은 사용하지 않는다.
- 초록/빨강 trading 의미를 Trust Status에 이식하지 않는다.

## 관련 Requirement ID

- 탐색: `REQ-FUNC-POINT-001` through `003`
- 판단 브리프: `REQ-FUNC-BRIEF-001` through `003`
- 신뢰상태와 근거: `REQ-FUNC-TRUST-001` through `005`
- 상태·접근성·운영 제약: `REQ-NFR-PERF-002`, `REQ-NFR-AVAIL-001`,
  `REQ-NFR-DATA-001` through `002`, `REQ-NFR-PRIV-001` through `002`,
  `REQ-NFR-COST-002`

## 핵심 사용자 흐름

1. 사용자가 포인트명 또는 지역을 입력한다.
2. 지원 후보를 이름, 지역 맥락, 선택적 유형으로 구분한다.
3. 사용자가 명시적으로 포인트를 선택한다.
4. 성공한 정보부터 판단 브리프가 표시되고 지연·실패 항목은 독립 상태로 귀결된다.
5. 사용자가 정보 슬롯의 신뢰상태와 시각 요약을 스캔한다.
6. 필요할 때 근거 상세를 열어 source, time, 상태 이유, 원문 또는 충돌 근거를 확인한다.
7. 미지원·모호·전체 실패 상태에서는 임의 브리프 없이 수정·재검색·가능한 재시도를 선택한다.

## 필수 화면과 상태

화면은 포인트 탐색, 복수 후보 구분, 판단 브리프, 근거 상세의 네 책임을 표현한다. 각 구조안은
loading, `POINT_UNSUPPORTED`, `POINT_AMBIGUOUS`, 정상 `CONFIRMED`, `PARTIAL_DATA`, `STALE`,
`UNVERIFIED`, `COLLECTION_FAILED`, `CONFLICT`, 전체 데이터 없음 상태를 포함한다.

## 정보 계층

1. 선택 포인트의 이름과 지역 맥락
2. 전체 데이터 가용성 요약(출조·법적 가능 판정이 아닌 비판정형 요약)
3. 가변 정보 슬롯: 라벨, 값 또는 값 없음, trust label, 기준시각/최근 확인일 요약
4. 항목별 근거 열기
5. 상세 source, 시간, 상태 이유, source_reference, 필요 시 양쪽 conflict 근거

정보 항목명과 값은 프로토타입 검증용 샘플일 뿐 OD-01의 실제 필드 결정을 의미하지 않는다.

## Progressive Disclosure

- 1차 브리프에는 항목 라벨·값·상태·시각 요약을 함께 둔다.
- 상세 근거는 행 확장, side panel, drawer 중 구조안에 맞는 방식으로 열되 키보드로 접근 가능해야
  한다.
- `CONFLICT`는 요약에서도 양쪽 근거가 존재함을 알리고 상세에서 대칭적으로 보여준다.
- `STALE`과 `COLLECTION_FAILED`를 하나로 합치지 않으며, 캐시 사용과 최근 수집 실패를 함께
  설명할 수 있다.

## 접근성

- 모든 신뢰상태는 텍스트 라벨과 아이콘/형태를 함께 사용한다.
- 키보드 초점 순서는 검색 → 후보 → 선택 → 브리프 슬롯 → 근거 상세 → 재시도 순으로 예측
  가능해야 한다.
- 최소 44px 행동 영역, 명시적 focus ring, 의미 있는 제목·상태 live region을 사용한다.
- 충돌 근거는 좌우 색상 대비에만 의존하지 않고 출처명과 “상충” 표기를 각각 제공한다.

## 모바일 기준

- 640px 미만에서 단일 열로 재배치하며 검색과 결과를 먼저 유지한다.
- 후보와 브리프를 동시에 좁게 압축하지 않고 선택 후 브리프로 전환한다.
- 표 형식은 라벨-값 카드/행으로 재배치하고 가로 스크롤을 핵심 흐름에 요구하지 않는다.
- 보조 공간 맥락은 축소·접힘 가능하며 지도 없이도 검색, 선택, 브리프, 근거 확인이 완결된다.

## 샘플 데이터 규칙

- 샘플 포인트·지역은 fixture이며 OD-03의 실제 POC 범위를 확정하지 않는다.
- 샘플 정보 슬롯은 구조 검증용이며 OD-01의 최소 정보세트를 확정하지 않는다.
- 샘플 freshness 시각은 상태 variant 시각화용이며 OD-02 임계값을 정의하지 않는다.
- 어떤 샘플도 추천점수, 안전·법적 가능, 조과 예측을 표시하지 않는다.
- 사용자 정확 GPS와 개인정보는 샘플·로그·화면의 기본 입력으로 사용하지 않는다.

## 비교할 구조안

- **A — Search-first**: 검색 → 구분 가능한 후보 목록 → 선택 → 브리프. 지도 비의존.
- **B — Map-first**: 공간 패널을 먼저 보여주고 검색·목록을 보조 제공. 지도 표현은 SDK 결정을
  의미하지 않음.
- **C — Hybrid**: 검색·목록을 주 흐름으로 유지하면서 선택적 공간 맥락을 보조 패널에 제공.
  지도 서비스가 없어도 P1 흐름 유지.
