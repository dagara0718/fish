# v1.4 product delta — environment-based species guidance

Baseline: v1.3 + KHOA live-connection hotfix (`749e241`). Adds a second, independent assessment
alongside the existing official KHOA species index: an explainable, rule-based estimate of which
supported species' documented environmental preferences currently match the point's observed
conditions. Does not touch NAVER map integration, the Worker, the Demo fixture app, or KHOA
connectivity — those stay exactly as verified in v1.3/hotfix.

## Product goal

Answer: "지금 이 포인트의 수온·계절·물때·시간대를 볼 때 어떤 어종에게 환경이 상대적으로 잘 맞는가?"
This is not a catch-probability model. No percentage, no "잡힐 확률", no "AI 추천" — see §Vocabulary.

## Governing constraints (non-negotiable for this delta)

- `ENVIRONMENT_BASED_GUIDANCE` and `OFFICIAL_FISHING_INDEX` are never merged into one score or one
  badge. Official grade/score is never a computation input for guidance (§REQ-FUNC-GUIDANCE-003).
- No AI/ML claim. This is a documented, testable, deterministic rule set — see `scoring-policy.ts`.
  No probability calibration is claimed because there is no labeled catch dataset to calibrate against.
- A species with no cited-evidence `SpeciesProfile` is never assigned a guidance result. KHOA's
  "기타어종" is excluded from guidance by construction (never has a profile).
- Missing environmental data or missing profile evidence produces `UNKNOWN` per factor, never a
  fabricated value, and never a MISMATCH-by-default.
- No directional current/water-mass data is used. `minCrsp`/`maxCrsp` is speed-only per the KHOA
  contract; direction is never inferred from it. See `research/marine-current-source-review.md`.

## New requirements

US11 — environment-based species guidance
- `REQ-FUNC-GUIDANCE-001`: a selected official point renders a separate "환경 기반 예상어종" section,
  producing `EnvironmentBasedSpeciesGuidance[]` — one entry per supported species with a profile,
  independent of and alongside `OFFICIAL_FISHING_INDEX` results.
- `REQ-FUNC-GUIDANCE-002`: each result carries `factors: FactorResult[]`, one row per recognized
  factor (`WATER_TEMPERATURE`, `SEASON`, `CURRENT_SPEED`, `TIDE`, `TIME_OF_DAY`), each with a status
  (`MATCH` | `PARTIAL_MATCH` | `MISMATCH` | `UNKNOWN`) and a plain-language reason. A factor without
  profile evidence renders as `UNKNOWN`, never a mismatch, never omitted from the row list.
- `REQ-FUNC-GUIDANCE-003`: guidance computation never reads `officialGrade`/`officialScore` as an
  input. Verified by a unit test asserting identical guidance output regardless of official grade.
- `REQ-FUNC-GUIDANCE-004`: no species is added to guidance output unless it has a `SpeciesProfile`
  with at least one cited `evidence` entry. "기타어종" is permanently excluded.

US12 — species profile data
- `REQ-FUNC-PROFILE-001`: `SpeciesProfile` records are version-stamped (`profileVersion`), carry
  `evidence[]` (`sourceTitle`, `sourceOrganization`, `sourceUrl`, `retrievedAt`, `supportedClaim`), and
  live in `src/species-guidance/species-profiles.ts`, separate from rendering code.
  Sourced in `research/species-environment-evidence.md`.
- `REQ-FUNC-PROFILE-002`: an unconfirmed characteristic is `undefined` on the profile (renders
  `UNKNOWN`), never a guessed numeric range.

US13 — evidence sufficiency and suitability policy
- `REQ-FUNC-GUIDANCE-005` (minimum evidence): guidance requires `WATER_TEMPERATURE` to be evaluable
  (species has a temperature range AND the environment snapshot has a water temperature) **and** at
  least one other factor evaluable (not `UNKNOWN`). Below this, the result is
  `INSUFFICIENT_EVIDENCE` with the factor rows preserved (so the user still sees what was and wasn't
  available) — never silently dropped.
- `REQ-FUNC-GUIDANCE-006` (suitability, `HIGH`/`MODERATE`/`LOW`/`INSUFFICIENT_EVIDENCE` — see
  `scoring-policy.ts` for the exact, tested rule): documented as an explainable rule, not a
  probability. No percentage is ever rendered.
- `REQ-NFR-TRUST-006`: guidance carries its own `TrustStatus`, propagated from the environment
  observations it was computed from (stale environment ⇒ stale guidance). A `HIGH` suitability with
  `UNVERIFIED`/`STALE` trust is a valid, expected combination — suitability is never auto-promoted to
  `CONFIRMED`.

US14 — marine current boundary (not connected)
- `REQ-NFR-CURRENT-001`: `minCrsp`/`maxCrsp` (유속) is speed-only per the existing KHOA contract; no
  direction is inferred from it in any code path.
- `REQ-NFR-CURRENT-002`: `MarineCurrentProvider` is a typed boundary
  (`getCurrentDirection(point): Promise<{status:'NOT_CONNECTED'}>`), shipped with exactly one
  implementation (`NotConnectedMarineCurrentProvider`) in v1.4. The UI states the limitation
  explicitly. See `research/marine-current-source-review.md` for the candidate API and why it is not
  wired up yet.

## Vocabulary (enforced by test, see §Tests)

Allowed: 환경 기반 예상어종, 환경 적합도 (높음/보통/낮음), 판단 근거 부족, 현재 환경과 잘 맞는 어종,
판단 근거. Forbidden anywhere in this feature's rendered text: AI 추천, 잡힐 확률, 조과 확률, `%`
followed by 확률-adjacent text, 무조건 잡힘, 출조 추천, 베스트 어종.

## Suitability rule (documented, not "scientific probability")

Implemented in `src/species-guidance/scoring-policy.ts`, exact thresholds tested in
`tests/unit/species-guidance-scoring.test.ts`:

- **INSUFFICIENT_EVIDENCE**: fewer than 2 evaluable (non-`UNKNOWN`) factors, or `WATER_TEMPERATURE`
  itself is `UNKNOWN`.
- **LOW**: `WATER_TEMPERATURE` is `MISMATCH` (observed range does not overlap the tolerated range at
  all).
- **HIGH**: `WATER_TEMPERATURE` is `MATCH` (overlaps the preferred range) and no other evaluable
  factor is `MISMATCH`.
- **MODERATE**: everything else evaluable (temperature `PARTIAL_MATCH`, or `MATCH` with another
  factor `MISMATCH`, or `MATCH`/`PARTIAL_MATCH` mixed with `PARTIAL_MATCH` elsewhere).

This is a small, fully-enumerable decision table — not a weighted score, not a percentage, not a
model. Given the current evidence base (§species-environment-evidence.md), two of six supported
species (농어, 감성돔) have no documented season/current/tide/time-of-day claim at all, so with only
`WATER_TEMPERATURE` ever evaluable for them, they can only ever land on `INSUFFICIENT_EVIDENCE`
in v1.4. This is the honest consequence of thin evidence, not a bug — softening the rule to force a
result for those two species would be exactly the kind of fabrication this delta exists to prevent.

## Supported species (v1.4)

우럭, 참돔, 감성돔, 농어, 돌돔, 벵에돔 — the species observed in the real KHOA response during v1.3
verification. "기타어종" is excluded by construction (no profile exists or ever will without a cited
species-level claim). A future KHOA species not in this list renders in `OFFICIAL_FISHING_INDEX`
normally; it simply gets no `ENVIRONMENT_BASED_GUIDANCE` entry until a profile is researched and added.

## Selected-vs-arbitrary-location note (reuses v1.3 policy)

Guidance is always computed from the confirmed official point's own environment snapshot, never from
raw click coordinates. When the point was reached via an arbitrary map click, the existing v1.3
"공식 기준 포인트의 환경 데이터를 사용했습니다" distance framing already covers this; v1.4 adds no new
distance policy.

## UI order in the detail panel

1. 낚시 이용 상태 (unchanged)
2. 오늘 확인할 어종 (unchanged, official summary)
3. 공식 바다낚시지수 (unchanged)
4. **환경 기반 예상어종 (new)** — top-level suitability + collapsible "왜 이렇게 판단했나요?" factor
   detail per species; no more than the supported species with a profile ever appear here.
5. 현재 환경 (unchanged)
6. 데이터 근거 (unchanged)
